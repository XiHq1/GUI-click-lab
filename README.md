# GUI 定位预研：多看一眼、多想一步，到底值多少？

> 面向 GUI 智能体的"推理价值校准"课题的前期预研。
> 用一个带精确标准答案的测试集，测量**补充观测**与**追加推理**相对**直接执行**的增量收益。

**结论先行**

| 路径 | 命中率（3 次运行） | 相对直接执行 |
|---|---|---|
| P0 直接执行 | 71.3 ± 5.3% | — |
| **P1 补观测**（裁剪放大） | **82.8 ± 3.4%** | **+11.5 pp** |
| **P2 追加推理**（先分析再答） | **56.3 ± 7.2%** | **−14.9 pp** |

- 补观测**稳定有效**：三次 Δ 分别为 +13.8 / +10.4 / +10.3，全为正，波动远小于效应量。
- 追加推理**稳定有害**：三次 Δ 分别为 −3.4 / −24.1 / −17.3，全为负。
- 补观测**不是万能的**：每次都有 4–7 个失败样本的裁剪窗口里根本没有目标——因为 P0 已经偏得太远。

---

## 1. 研究目的

GUI 智能体执行任务时，可以"直接做"，也可以"再截一张局部图看看"或"再想一遍"。多投入不总是划算：

- 界面清晰、目标明确时，额外观测只会增加延迟；
- 界面拥挤、文字很小、目标被遮挡时，不看反而一定错。

现有方法多用**模型置信度**判断要不要加投入，但置信度低 ≠ 多看有用。本预研要回答的是：

> **在同一张截图上，"补一次观测"和"追一次推理"相对"直接执行"，命中率到底提升/下降多少？代价是多少？**

这是正式课题（收益预测 + 校准 + 自适应执行）的第一步：先把"增量收益"这个因变量测准。

## 2. 实验方法

### 2.1 测试集

合成界面截图（1920×1080，脚本绘制），29 个带精确矩形框的目标：

| 类型 | 数量 | 设计意图 |
|---|---|---|
| 普通按钮 | 24 | 12px 字号，6×4 网格，间距仅 10px |
| 极小字号 | 2 | 9px，逼近"看不清"的边界 |
| 相似文案 | 3 | 「提交」「提交并关闭」「提交并新建」 |
| 遮挡 | 其中 4 个 | 被半透明"加载中"面板覆盖 |

选择合成界面的原因：**只有它能提供精确坐标作为标准答案**，且难度可按需调节（17px → 12px → 9px）。

### 2.2 三条路径

同一个目标、同一张截图，各问一次：

| 路径 | 干预方式 | 额外成本 |
|---|---|---|
| **P0 直接执行** | 整图提问 | 基准 |
| **P1 补观测** | 以 P0 预测点为中心裁 320px 窗口，放大到 1024×1024 再问 | +1 次调用 |
| **P2 追加推理** | 同一张图，要求"先说明位置/周围/易混项，再给坐标" | +1 次调用，更长输出 |

P1 要求模型输出 **0–1000 的相对坐标**，映射时不依赖任何画布尺寸——这是踩过坑之后的结论（见 §6）。

### 2.3 判分

- **命中**：预测点落在目标矩形内（`x∈[x1,x1+w1]` 且 `y∈[y1,y1+h1]`）。
- **误差**：预测点到矩形中心的欧氏距离（像素）。
- 逐样本记录模型原始输出、坐标、延迟、token，落盘为 CSV/JSONL。

### 2.4 坐标画布标定

实测该 API 会把输入图缩放到 **1024×1024** 再输出坐标。用 5 个已知目标反推：

```
102 × 1920/1024 = 191   （真实 198，差 7px）
782 × 1920/1024 = 1466  （真实 1452，差 14px）
```

不标定就会得到"全部偏到角落"的假象——早期版本正是因此把命中率误判为 0%。

### 2.5 重复

同一配置运行 **3 次**。原因：单次波动可达 10 个百分点（P0 在 65.5%–75.9% 之间），
不重复就无法区分"方法有效"和"这次运气好"。

## 4. 分析

**① 补观测的收益是真实且稳定的，但不是免费的。**
三次都提升 10–14 个百分点，标准差仅 3.4。但每次都有 1 个"弄坏"（原本对、看了反而错）。

**② "裁剪没框住目标"是全部结论的关键。**
每次有 4–7 个失败样本，其裁剪窗口里**根本没有目标**——P0 已经偏出 320px。
这说明补观测的收益取决于"当前偏差是否落在可补救范围内"，**而这一点在看到结果前可预测**。
这正是"推理价值校准"的落点：与其固定补观测，不如预测"这次补了有没有用"。

**③ 追加推理反而更差（三次一致）。**
可能机制：模型对位置的自我描述本身是错的，随后照着错误描述去点（自我锚定），
或分析占用了定位所需的注意力。这与 *To CoT or not to CoT* 的结论一致，也直接支持"多算 ≠ 更准"。

## 7. 局限

1. **单步、无执行**：测的是"指得准不准"，不是"点下去对不对"，更不是任务成功。
2. **合成界面**：复杂度和视觉噪声低于真实桌面软件。
3. **样本量小**：29 个目标 × 3 次，只能估计量级，不做显著性检验。
4. **单一模型**：只有 `qwen3-vl-plus`，未验证跨模型可迁移性。
5. **P1 策略朴素**：固定 320px 窗口、围绕 P0 预测点；换策略结果会变。
6. **画布依赖部署**：1024×1024 是该 API 的实现细节，换部署需重新标定。
7. **无等待对照**：页面是静态的，"等一会儿再看"与"直接看"没有区别。

## 9. 总结

> 在 29 个目标的合成定位测试集上，`qwen3-vl-plus` 的直接定位命中率为 71.3±5.3%。
> 追加一次局部放大观测后提升至 82.8±3.4%（+11.5pp，三次运行全为正）；
> 追加一次"先分析再回答"的推理后降至 56.3±7.2%（−14.9pp，三次全为负）。
> 补观测的收益依赖"当前偏差是否在可补救范围内"——每次均有 4–7 个失败样本的裁剪窗口不含目标。
> 这表明**干预的价值是可以事前预测的**，构成后续"推理价值校准"研究的直接动机。
