# 从零开始：不插虚拟机的 GUI 定位实验

> 目标（今天就能完成）：让模型看一张 1920×1080 的界面截图，说出「保存文档」这个按钮在哪，
> 然后自动算出**命中率、像素误差、单步延迟**——这是你整个项目最小的一块地基。
>
> 不需要虚拟机、不需要 pip install、不需要 GPU（最后接真模型时才需要）。

---

## 0. 先看懂这条链路

```
shot_1920.png ──缩放──> shot_1280.png ──base64──> 模型
                                                   │
                                          "<point>x,y</point>"
                                                   │
                          换算：×(1920/1280) ──────┘
                                                   ↓
                        与 labels.json 的标准答案比对
                                                   ↓
                        命中率 / 像素误差 / 延迟 → results.csv + report.html
```

**关键点**：模型看到的是 1280×720 的图，屏幕上真实坐标是 1920×1080，
所以模型说 `(134, 154)`，真实位置是 `(134×1.5, 154×1.5) = (201, 231)`。
**这一步换算写错，后面所有结论全错。**

## 1. 这套文件各自干什么

| 文件 | 作用 | 你要不要改 |
|---|---|---|
| `make_test_image.ps1` | 画一张假的软件界面，同时输出**标准答案**（每个按钮的坐标） | 不用改，想换布局可以改 |
| `labels_source.json` | 界面上的文字（20 个常用操作 + 4 个禁用 + 3 个相似项） | 可以改，改成你要测的文案 |
| `labels.json` | 脚本自动生成：每个元素的 id/文案/坐标（1920 与 1280 两套） | **不要手改** |
| `shot_1920.png` / `shot_1280.png` | 截图原图 / 喂给模型的图 | 自动生成 |
| `probe.py` | 主实验：调模型 → 解析 → 换算 → 打分 → 出报告 | 核心，可以改 prompt |
| `selftest.py` | 不开浏览器、不联网，验证解析/换算/打分对不对 | 不用改 |
| `ping_model.py` | 连不上模型时先跑这个，逐项排查 | 不用改 |
| `page.html` | 一个真网页版本的同一套按钮，**下一步（虚拟机/浏览器）才用** | 备用 |

## 5. 第 3 步：接真模型

两条路线，**先走 A**，跑通再考虑 B。

### 路线 A：LM Studio（图形界面，最省心）

1. 下载安装 LM Studio（Windows 版）。
2. 搜索并下载模型：`Qwen3-VL-8B-Instruct` 的 **Q4_K_M / 4-bit** 量化版（约 5–6 GB）。
   - 别下 bf16（16 GB 显存，你只有 8 GB）
3. 加载模型，把设置调成：
   - **Context Length**：8192（不要 32k，会爆）
   - **GPU Offload**：拉到最大
   - **不要**开启“自动缩放图片”之类的选项
4. 切到 **Developer** 页签 → **Start Server**（默认端口 1234）。
5. 回到 PowerShell 验证：

```powershell
python ping_model.py --base-url http://127.0.0.1:1234
```

它会打印“可用模型”、原始输出、耗时。看到 `✓ 解析到坐标` 就说明通了。

6. 跑正式实验（把模型名换成上一步列出的那个）：

```powershell
python probe.py --base-url http://127.0.0.1:1234 --model qwen3-vl-8b-instruct
```

### 路线 B：llama.cpp（可控，写论文时推荐）

1. 从 llama.cpp 的 releases 下载 **Windows CUDA 版**（文件名类似 `llama-bXXXX-bin-win-cuda-x64.zip`）。
2. 下载两个文件：`Qwen3-VL-8B-Instruct-Q4_K_M.gguf` 和 `mmproj-F16.gguf`（多模态必须配对）。
3. 启动服务：

```powershell
.\llama-server.exe -m .\models\Qwen3-VL-8B-Instruct-Q4_K_M.gguf `
  --mmproj .\models\mmproj-F16.gguf -ngl 99 -c 8192 --flash-attn --no-mmap `
  --host 127.0.0.1 --port 8080
```

4. 跑：

```powershell
python probe.py --base-url http://127.0.0.1:8080 --model qwen3-vl-8b
```

### 8 GB 显存的三条红线

| 红线 | 原因 |
|---|---|
| 只用 4bit 量化（Q4_K_M / AWQ） | 8B 的 bf16 要 16 GB，直接 OOM |
| context ≤ 8192 | KV cache 随上下文线性涨，图片 token 很占 |
| 图片已经是 1280×720，别让服务器再放大 | 视觉 token 翻倍，速度腰斩还容易 OOM |

## 6. 第 4 步：读结果

每次运行都会生成 `results\时间戳\` 三个文件：

**`results.csv`（最重要，后面画图全靠它）**

| 列 | 含义 |
|---|---|
| `label` | 目标文案 |
| `raw` | 模型原始输出（排查格式问题看这列） |
| `px, py` | 模型给出的坐标（1280 空间） |
| `sx, sy` | 换算到 1920 屏幕后的坐标 |
| `dist` | 到标准答案中心的像素距离 |
| `hit` | 是否落在按钮框内（True/False） |
| `latency` | 这次调用耗时（秒） |

**`summary.json`**：总体命中率、平均误差、P50/P95 延迟，以及按元素类型（`btn`/`tri`）分组统计。
分组很重要——如果 `btn` 90%、`tri` 30%，说明模型分不清“确认提交/确认并提交”，这是**语义歧义**，不是看不清。

**`report.html`**：一眼看全。红点在框外的地方，就是模型翻车的地方。

## 7. 第 5 步：怎么判断

| 结果 | 说明 | 下一步 |
|---|---|---|
| 命中率 ≥ 70% | 模型可用 | 进入三路实验（§9） |
| 30%–70% | 先别怀疑模型 | 90% 是坐标换算/约定错了，见下面“坐标全偏”排错 |
| < 30%，且红点都在按钮上 | 是“点没生效”或字体太小 | 检查图像清晰度、模型分辨率设置 |
| 延迟 > 8 s | 太慢，影响后续实验 | 降到 960×540，或换 Qwen3-VL-4B |

### 排错表

| 症状 | 最可能的原因 | 怎么修 |
|---|---|---|
| `连不上：ConnectionRefused` | 模型服务没开 | LM Studio 点 Start Server；llama.cpp 看进程是否在 |
| `可用模型：[]` | 服务开了但没加载模型 | 先加载模型再 Start Server |
| `解析失败，原始输出：'...'` | 模型没按格式回 | 看 `raw`，可能是聊天口吻；把 `max_tokens` 调小、prompt 加重“只输出一行” |
| 坐标全偏到左上角/右下角 | 模型输出是 0–1000 归一化 | 加参数 `--coord-mode norm1000` |
| 坐标 x 都 ≤ 1000 但屏幕宽 1920 | 同上 | 同上 |
| 误差固定为“刚好 1.5 倍” | 你重复缩放了一次 | 检查是不是既缩了图又乘了比例 |
| 显存不足 / 掉驱动 | 用了 bf16 或 ctx 太大 | 换 Q4_K_M，ctx 4096 |
| 中文显示成方块 | 终端编码 | `chcp 65001` 后重跑 |

## 9. 下一步：三路实验怎么长出来

现在 `probe.py` 只做了「直接问」这一路。把它扩成三路，就是申报书里的核心实验：

| 路径 | 怎么改 | 预期 |
|---|---|---|
| **P0 直接执行** | 现在的版本 | 基线 |
| **P1 补充观测** | 先用 PowerShell 把目标区域裁出来放大成 2 倍，再问一次；或把整图放大到 1920 再问 | 命中率涨，延迟也涨 → 就有了“值不值” |
| **P2 追加推理** | 同一次调用里加“先描述界面结构，再给坐标”；或问两遍取一致的那个 | 有时涨，有时不涨 → 这就是“收益异质” |

有了三路，你就能填 `Δ命中率` 和 `Δ延迟`，`u = Δ − λ·c` 才成立。
**这就是从“跑通”到“有研究结论”的那一步。**

## 10. 这套东西的边界（写论文时要诚实说明）

1. **它是静态截图，不是真执行**：命中 ≠ 任务成功，只测“定位”。
2. **没有等待对照**：页面不会自己变化，所以 P3 恒等于 P0（这正是后面必须上 OSWorld 的原因）。
3. **1280×720 是 8 GB 显存的妥协**：真实桌面是 1920×1080，缩放本身会损失小字细节——这本身也可以作为一个消融项。
4. **单模型、单页面**：还不能说明跨界面泛化。
